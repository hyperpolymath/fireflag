=== Banned-language violation (CRITICAL)

FireFlag's *test suite is written in banned TypeScript*. 3,028 LOC
across 6 `.ts` files:

[cols="3,1,3"]
|===
| File | LOC | Type evidence

| `tests/unit/flag_evaluation_test.ts` | 555 | interface declarations, type annotations
| `tests/unit/types_test.ts`           | 544 | `interface FlagDatabase { … }`, `function validateFlagKey(key: string): boolean`
| `tests/property/flag_properties_test.ts` | 499 | typed generics
| `tests/e2e/extension_lifecycle_test.ts`  | 649 | typed
| `tests/aspect/security_test.ts`          | 473 | typed
| `tests/bench/flag_bench.ts`              | 308 | typed
|===

Verified TypeScript (not just `.ts` extension) by inspecting
`tests/unit/types_test.ts` lines 60-120 — interfaces, type annotations
(`key: string`, `Record<string, CategoryMeta>`), optional-field syntax
(`lastModified?: number`), union types (`"user" | "extension" | "system"`).

Per the repo-local `.claude/CLAUDE.md` (system reminder surfaced this
audit) and estate CLAUDE.md:

- BANNED: TypeScript → replacement: ReScript.
- `deno.json` runs all tests via `deno test tests/`, so they execute as
  TypeScript despite the policy.

*Gamed workflow* — `.github/workflows/ts-blocker.yml` is the in-repo
policy enforcement. Its check is:

[source,yaml]
----
NEW_TS=$(git diff --name-only --diff-filter=A HEAD~1 | grep -E '\.(ts|tsx)$' | grep -v '\.gen\.' || true)
...
if [ -n "$NEW_TS" ] ...; then exit 1; fi
----

This only inspects the single most-recent commit's added files. The 6
`.ts` test files were all added in one commit (2026-04-04,
"Added comprehensive Deno test suite: 94 tests …"), then pushed — and
the repo stayed green. The blocker is effectively theatre:

. It only catches *newly added* `.ts` files, not committed ones, so
  the existing 3,028 LOC is invisible to it.
. Even for a single-commit PR, `HEAD~1` compares one commit back; a PR
  with its own merge-commit parent will silently bypass.
. There is no "existing .ts inventory" check in any other workflow.

This is the *exact self-knowing policy violation* the audit spec asks
about: a blocker workflow shipped as proof-of-compliance while banned
code coexists with it in the same tree.

== Verdict

*Current CRG grade: **D (Alpha)**. Demote one grade from self-declared C.*

Self-declared: *C*. Audited: *D*. This is a *one-grade honesty delta*,
smaller than neurophone's 2-grade delta but structurally similar: the
repo has *impressive-looking* per-feature artefacts (EXPLAINME,
SEMANTICS, Idris2 proofs, 94 tests) that defensibly clear the D bar,
but the C clause "deep per-file + per-directory annotation + dogfooded
+ CI green" is not met, *and* a grade-C claim over a banned-language
test suite with a gamed blocker workflow is the exact honesty pathology
v2.0 was designed to catch.

Reasoning (one sentence): fireflag meets structural RSR D-floor
comfortably and has unusually strong architecture-level annotation
(SEMANTICS.adoc + EXPLAINME), but its entire test suite is banned
TypeScript protected by a `ts-blocker.yml` that only checks the most
recent commit's additions — policy theatre — and the C-specific
clauses (per-directory annotation under `extension/`, populated
`[dogfooding-status]`, CI-green SHA recorded) are unmet.

Positive signals that earn the D and keep it out of E:

1. 94 `Deno.test(` + 29 `Deno.bench(` — filesystem-verifiable.
   Total-tests claim (94) matches exactly; benchmarks off by 1 (28
   declared, 29 actual).
2. Genuinely strong EXPLAINME.adoc + SEMANTICS.adoc + 9 Idris2 proof
   modules (1 568 LOC named `FlagSafety`, `FlagTransaction`,
   `SafeChecksum`, `SafeLRU`, `SafeQueue`, `SafeUI`, `SafeUrl`,
   `SafeVersion`, `SafeJson`). Zero dangerous patterns in `extension/`.
3. RSR structural compliance is genuine: 24 workflows (including
   npm-bun-blocker, ts-blocker, hypatia-scan, svalin-scan,
   vordr-verify), all 6 `.machine_readable/6a2/*.a2ml` files present
   (even if 5 are stubs), contractile trident with runners, Justfile +
   Mustfile, LICENSES/, guix.scm + flake.nix, .well-known/.

  Firefox extension store)` header form used on the extension
  runtime code is the *legitimate platform-required fallback* under
  Rule 2 of the estate licence policy — Firefox Add-ons requires an
  OSI-approved licence. This is not counted as a licence-policy
  violation.
- The Idris2 proof modules are *not* re-audited for proof-closure
  here. If the project wants to claim them as proven-code evidence at
  grade C/B, a separate proof-closure audit is needed (Idris2
  `check`, no `believe_me`/`assert_total` in `.idr` files, CI running
  on proof changes).
- README's "Completion: 99%" vs STATE's 75% is flagged but the audit
  does not itself re-score completion-percentage — it is not a v2.0
  grade criterion.
- The standing rule "GitHub is source of truth; other forges are
  mirror-driven" is respected in this audit — the five-push-remote
  config is flagged as a drift to fix, not a violation that changes
  the grade.
